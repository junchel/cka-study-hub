1. Troubleshooting (배점 30%)

문서 검색: `troubleshoot clusters`, `debug pods`

kube-apiserver 장애 복구

Static Pod

`kubectl` 명령어가 먹통일 때. 절대 `systemctl restart kube-apiserver` 하지 마세요 (서비스가 아닙니다).

# 1. kubelet 상태 확인
systemctl status kubelet
# 2. 매니페스트 오타 및 인증서 확인
vi /etc/kubernetes/manifests/kube-apiserver.yaml
# 3. containerd 컨테이너 로그 직접 조회
crictl ps -a | grep apiserver
crictl logs <container-id>

Worker Node NotReady

Kubelet & CNI

노드가 NotReady 상태일 때는 Kubelet 서비스와 CNI 플러그인을 점검합니다.

# 1. 노드 원인 파악
kubectl describe node <node-name>
# 2. 해당 노드 SSH 접속 후 Kubelet 로그 확인
systemctl status kubelet
journalctl -u kubelet -xe --no-pager -n 50
# 3. CNI 디렉터리 확인
ls -la /etc/cni/net.d/

로깅 사이드카 컨테이너 추가

YAML 계층 함정

기존 컨테이너가 파일로 쓰는 로그를 `kubectl logs`로 볼 수 있게 사이드카를 붙일 때 가장 잦은 실수는 YAML 들여쓰기입니다.

# spec.containers (X) ➔ Unknown field 에러 발생!
# 반드시 spec.template.spec 아래에 위치:
spec:
  template:
    spec:
      containers: [ ... ]
      volumes: [ emptyDir: {} ]

CrashLoopBackOff / 이전 로그 조회

--previous

컨테이너가 기동 즉시 죽어서 `kubectl logs`에 아무것도 안 나올 때는 이전 컨테이너 인스턴스의 로그를 확인합니다.

# 1. 이전 인스턴스 로그 확인
kubectl logs <pod-name> --previous
# 2. 컨테이너 종료 코드(Exit Code) 확인
kubectl describe pod <pod-name> | grep -A 5 "Last State"

2. Cluster Architecture (배점 25%)

문서 검색: `operating etcd clusters`, `upgrading kubeadm clusters`

etcd 스냅샷 백업 & 복원

`ETCDCTL_API=3` 필수! 복원 후 static pod 매니페스트의 hostPath를 변경해야 실제 반영됩니다.

# 백업 (인증서 3종 필수)
ETCDCTL_API=3 etcdctl --endpoints=https://127.0.0.1:2379 --cacert=/etc/kubernetes/pki/etcd/ca.crt --cert=/etc/kubernetes/pki/etcd/server.crt --key=/etc/kubernetes/pki/etcd/server.key snapshot save /root/etcd-backup.db
# 복원 (새 디렉터리로 복원)
ETCDCTL_API=3 etcdctl --data-dir=/var/lib/etcd-new snapshot restore /root/etcd-backup.db
# 주의: /etc/kubernetes/manifests/etcd.yaml 의 hostPath를 /var/lib/etcd-new로 변경!

CRD vs RBAC Subjects vs CSR (1회차 혼동)

문제에 `subject`라는 단어가 나왔을 때 CRD에 넣으려다 실패했던 함정입니다.

CRD: 리소스 타입 정의 (`kind: CustomResourceDefinition`). `subject` 필드 없음!
RBAC RoleBinding: `subjects` 배열에 User, Group, ServiceAccount를 매핑하여 권한 부여.
CSR: 클라이언트 인증서 subject (`CN`, `O`). signerName은 `kubernetes.io/kube-apiserver-client`.

Helm 저장소 등록 & 특정 버전 고정

지문에서 특정 버전을 설치하라고 할 때 `APP VERSION`이 아닌 `CHART VERSION`을 넣어야 합니다.

# 1. 레포 추가 및 업데이트
helm repo add <repo-name> <repo-url>
helm repo update
# 2. 사용 가능한 CHART VERSION 확인
helm search repo <repo-name>/<chart> --versions
# 3. 버전 지정하여 배포
helm install <release-name> <repo>/<chart> --version <CHART_VERSION> -n <ns>

kubeadm 클러스터 업그레이드 순서

drain ➔ kubeadm 업그레이드 ➔ kubeadm upgrade apply ➔ kubelet 업그레이드 ➔ uncordon

kubectl drain <node> --ignore-daemonsets
apt-mark unhold kubeadm && apt-get install -y kubeadm=1.xx.x-1.1 && apt-mark hold kubeadm
kubeadm upgrade plan && kubeadm upgrade apply v1.xx.x
apt-mark unhold kubelet kubectl && apt-get install -y kubelet=1.xx.x-1.1 kubectl=1.xx.x-1.1 && apt-mark hold kubelet kubectl
systemctl daemon-reload && systemctl restart kubelet
kubectl uncordon <node>

3. Services & Networking (배점 20%)

문서 검색: `dns for services and pods`, `network policies`, `ingress`

Pod DNS vs Service DNS (시험 함정)

지문에서 "lookup the DNS of the Pod"라고 했을 때 Pod 이름을 넣으면 0점입니다.

• Service DNS: <svc-name>.<namespace>.svc.cluster.local
• Pod DNS: <ip-with-dashes>.<namespace>.pod.cluster.local
예: Pod IP가 10.244.1.88, ns가 prod라면 ➔ 10-244-1-88.prod.pod.cluster.local

Ingress v1 필수 필드

v1beta1이 아닌 `networking.k8s.io/v1`을 사용하며, 아래 두 필드를 빠뜨리지 마세요.

1. spec.ingressClassName: "nginx" 등 명시
2. paths[].pathType: "Prefix" 또는 "Exact" 명시
3. backend.service.port.number: 숫자 포트 지정

NetworkPolicy AND vs OR 문법

하이픈(`-`) 위치 하나로 완전히 다른 정책이 됩니다.

# AND 조건 (해당 NS 내의 해당 라벨 Pod만 허용):
- namespaceSelector: { matchLabels: { team: dev } }
  podSelector: { matchLabels: { role: frontend } }
# OR 조건 (해당 NS의 모든 Pod 또는 모든 NS의 해당 라벨 Pod):
- namespaceSelector: { matchLabels: { team: dev } }
- podSelector: { matchLabels: { role: frontend } }

Service Endpoint 누락 디버깅

서비스를 생성했는데 트래픽이 안 통하면 가장 먼저 `kubectl get ep`를 봅니다.

# 1. 엔드포인트 확인 (비어있으면 selector 불일치)
kubectl get endpoints <svc-name> -n <ns>
# 2. Pod 라벨과 서비스 Selector 대조
kubectl get pods -n <ns> --show-labels
kubectl describe svc <svc-name> -n <ns> | grep Selector
